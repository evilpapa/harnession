# Harnession 需求与设计

## 目标

本地优先地发现和索引多个 AI Agent 的历史会话，以项目为中心跨工具查找工作记录。长期目标支持 Codex、Claude Code、Pi、OpenCode、Hermes Agent、Antigravity，以及 Windows、Linux、macOS。覆盖范围受可访问数据、Agent 版本及格式影响，无法保证发现云端、删除或不可解析的数据。

## 用户需求

1. 展示数据源、扫描结果、错误和覆盖限制；允许配置数据位置。
2. 发现并增量索引会话，保留来源、原始 ID、时间、项目和可读内容。来源不可访问或解析失败时保留旧索引。
3. 以 Git 仓库根目录或工作目录关联项目；识别常规 worktree，提供手动纠错并在重新扫描后保留。
4. 按项目、Agent、时间和内容检索、浏览会话；未识别项目归为未归类。
5. 后续支持标签、备注、原 Agent 恢复、交接摘要、可选语义搜索及图形界面。
6. 本地处理、原始来源只读；任何外部模型传输必须由用户启用。清理索引不影响源数据。

## 产品范围与优先级

| 优先级 | 需求 | 验收要点 |
| --- | --- | --- |
| P0 | 数据源发现和同步 | 支持自定义位置，显示扫描时间、数量和错误；源不可用时保留已索引内容。 |
| P0 | 项目与会话浏览 | 同一项目的不同 Agent 会话集中展示；保留工作目录与来源；无法识别时显示未归类，支持手动修正。 |
| P0 | 搜索与筛选 | 根据项目、Agent、时间和内容查找，提供可定位的结果；基础搜索不依赖外部服务。 |
| P0 | 隐私和数据完整性 | 默认只读来源、本地处理；删除索引不影响来源；解析不完整或失败时明确展示。 |
| P1 | 整理和恢复 | 收藏、标签、备注、批量整理；仅在对应 Agent 支持时提供原会话恢复。 |
| P1 | 导出和交接 | 允许预览、选择并导出内容；交接摘要包含目标、进度、决策、验证与待办，跨 Agent 交接视为新会话。 |
| P2 | 智能能力与扩展 | 可选摘要、语义搜索、远程来源和多设备支持；外部模型传输须由用户明确启用。 |

以上是产品目标，不代表第一版均已实现。尤其是五种 Agent 的会话覆盖取决于本地数据、版本和可解析格式；云端、已删除及加密记录不保证可用。项目自动关联应保留依据，支持撤销，不能仅凭目录名或 remote 相同合并。

## 跨平台要求

- macOS、Linux 和 Windows 使用各平台的数据目录及路径约定，允许覆盖数据源和索引位置。
- 适配器不依赖特定 shell；外部命令依赖及缺失时的行为必须明确。源码数据只读，索引与用户元数据独立保存。
- 在各系统的自动化测试中覆盖路径、Unicode、权限、数据库读取和增量扫描；在完成实机或 CI 验证前不宣称兼容。

## 第一版设计

- Python 标准库实现 CLI，SQLite 作为本地索引，不访问网络。
- 来源：Codex JSONL（可调用系统 zstd 处理压缩记录）、Claude Code JSONL、Pi JSONL（v1–v3）、Hermes SQLite（只读连接）。每个会话按 Agent + 来源路径去重；Hermes 使用数据库路径和原始 ID。
- Pi 默认扫描 `~/.pi/agent/sessions`，支持 `PI_CODING_AGENT_DIR`、`PI_CODING_AGENT_SESSION_DIR` 和 `scan --pi` 覆盖。使用头部 ID/cwd、记录时间戳和最新会话名称；清除名称时回退首条用户文本。每个文件汇总所有分支的对话、工具调用与输出、已记录的思考和系统提示，保留压缩前原始消息，不重建当前分支或模型上下文。扩展状态与未知事件忽略，未知版本或损坏记录报告失败并保留旧索引。
- Antigravity 只读扫描桌面版和 CLI 的本地 SQLite 会话及明文 JSONL 转录，按原始会话 ID 去重。首个本地工作区用于项目归类，范围覆盖普通用户和助手文本。没有明文转录的旧版 `.pb` 会话会报告失败。
- 文件适配器按修改时间和大小增量判断；逐个读取失败时记录错误并保留旧记录。Hermes 当前全量读取。每次扫描结束保存数据源状态；已删除的来源不会自动删除索引。
- 项目使用工作目录上溯 Git 根目录；常规 Git worktree 归入主仓库。无法找到 Git 根目录时使用工作目录。用户覆盖单独存储，不被扫描覆盖。
- 对话、工具调用与输出、思考和系统/开发者提示用于检索；技术记录独立分类且默认折叠，`AGENTS.md instructions`、`Role` 和明确的环境/技能注入块使用独立指令标签。列表摘要使用最后一次用户提问，排除指令、工具结果和助手回复；同一原始提问中被指令分隔的普通文本合并展示。子串搜索支持中文，无需分词。数据模型保留源路径便于扩展和核查。
- 系统数据目录按平台确定，路径处理使用 pathlib。压缩依赖外部 zstd；跨平台打包时需要提供可用的解压方案。

## 第一版验收

扫描后可查看来源状态；能列出并按项目和内容过滤已解析会话；详情可查看来源与文本；手动归属在重新扫描后保留；失败不会静默删除已有索引；原始数据只读。对不支持和解析失败的情况明确提示。

## 桌面实现进展

已新增 `apps/desktop` 的 Tauri / Rust + React 工作台和结构化 JSONL gateway：支持真实索引浏览、Chat/终端风格记录/并排阅读、显式图片附件、数据源配置及桌面 PTY。旧 CLI 和手动项目归属保持可用。结构化消息按来源重新读取，旧文本不按角色前缀拆分；来源失败时保留快照。

当前按对话、工具调用与输出、思考、系统/开发者提示及明确图片引用建立快照。仅收集来源已保存的内容，加密或脱敏思考标注不可读；技术记录在 Chat 和 TUI 中默认折叠，展开后按文本阅读并可完整复制。解析器升级后通过重新扫描补采已有会话，保留会话身份和手动归类。新的 PTY 运行与历史会话分开，原生恢复、结构化实时 Chat、文件监控和终端持久录制尚未实现。具体启动、验证与边界见 [桌面开发说明](desktop-development.md)。

## 已知限制与路线

OpenCode 适配待调研；Pi 已使用本机 v3 会话验证，v1/v2 仅以构造样本覆盖，分支恢复与上下文重建不在当前范围；Hermes 不同版本的结构、非 CLI 来源与项目语义待验证；跨平台和大规模性能验证仍待完成。桌面已有基础分页与图形界面，尚缺来源删除识别、归档、时间筛选、全文索引和全量虚拟化。后续逐项添加来源格式样本、系统 CI 和覆盖率报告，再实现恢复、交接与可选摘要。未经验证不自动合并同名项目或不同仓库。
